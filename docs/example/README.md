# docs/example

一条 4 分 01 秒的中文视频（AI 新模型测评），三份文件都是完整版，用来给第一次用的人看格式。

**这是 fixture，不是某次真实运行的原始输出**：文案来自真实转写，`avg_logprob` 为了构造演示
场景做过规则化（143 段只有 8 个不同取值，所以 `⚠` 集中在一处）。读它看格式，别拿它推断
置信度分布或摘要质量。

| 文件 | 说明 |
|---|---|
| `transcript.md` | 完整（143 段）。每段一行，带 `[mm:ss]`（满一小时 `[H:MM:SS]`，四舍五入到秒）、低置信 `⚠`、每 5 分钟分章 |
| `summary.md` | 完整。抽取式 9 条，每条要点带 `[mm:ss]`，回查不过的已被删 |
| `segments.json` | 完整。段级 `avg_logprob` / `no_speech_prob` / `compression_ratio` / `temperature` |

## 这份输出能说明什么

1. **引用是逐段可查的**：`[00:09]` 就是第 9 秒，不是"大概在开头"。
2. **摘要每条都带出处**：要点必须是原文（或合并后的短段块）的子串，时间戳落在该块范围内
   （前后各留 1 秒），否则删掉。
3. **它确实会错**：`Cloud` 应该是 `Claude`、`GPD` 应该是 `GPT`、`Sau` 应该是 `Sora`。
   这不是 bug，是 480 MB 小模型对专有名词的常态——`vsum fix` 就是干这个的，
   但词表得你自己加（包里的 `terms.json` 只是示例）。
4. **摘要很短**：4 分钟 143 段，只摘出 9 条。宁可少，不可错。

## 复现

```bash
vsum 你的视频.mp4 -o out/
vsum find out/ "美元"          # 在这份示例里能命中 16 处；换你自己的关键词
```

模型、设备、解码参数都在 `manifest.json` 里；这份示例的模型是 `small`（头部的 `model` 只记名字，
不记本机路径）。
